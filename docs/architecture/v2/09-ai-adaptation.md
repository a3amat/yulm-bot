# 09. AI-адаптация контента

## Что делает ИИ в продукте (не «чат-бот», а конвейер)

Вход: версия материала (Markdown + медиа). Выход: **AdaptedPayload** под конкретный канал — готовый к отправке и к ручному редактированию. Операторы конвейера применяются по профилю канала (берём из `capabilities` адаптера):

| Оператор | Пример |
|---|---|
| `fit_length` | статья 8000 знаков → пост TG ≤1024 со ссылкой на оригинал; X ≤280 или тред |
| `reformat` | Markdown → HTML для блога, plain+эмодзи для VK, карточки-подписи для IG |
| `tone_rewrite` | «строгий пресс-релиз» → «живой пост сообщества» (тон workspace'а сохраняется в профиле бренда) |
| `thread_split` | логическая разбивка на N связанных постов с нумерацией |
| `media_caption` | alt-текст/подпись к картине (vision-модель), водяной знак не ИИ, а media-processor |
| `hashtags_title_cta` | релевантные хэштеги, заголовок, призыв к действию |
| `translate_localize` | RU→EN с учётом площадочных норм (не дословно) |

## Архитектура модуля

```
material.version.created ──► AI Worker
   профиль бренда (tone, banned words, подпись) + capabilities канала
        ▼
   prompt template (версионируемый, как код) ──► LLM Router (OpenAI/Anthropic/local vLLM)
        ▼                                          ▲ fallback, cost per model
   structured output (JSON schema: title, body, media_refs, thread[])
        ▼
   post-validators (лимиты символов, forbidden words, ссылки) ── не прошёл → авторетрай с исправлением
        ▼
   AdaptedVariant (draft) → UI diff-view → принимает / правит / отклоняет человек
```

Ключевые решения:
- **Structured output**: модель обязана вернуть JSON по схеме (function calling / response_format); парсер строгий, лишний текст отсекается. Никакого «свободного текста» в publish payload.
- **Human-in-the-loop по умолчанию**: AI никогда сам не публикует; результат — вариант черновика. Автопубликцию включаем позже как opt-in Pro-фичу с whitelist каналов.
- **Промпт-шаблоны в git**, версионируются, тестируются golden-set'ами (набор материалов + ожидаемые свойства результата: длина, наличие CTA, тон). Прогресс моделей = регрессия качества без тестов невозможна.
- **Cost control**: бюджет на workspace/месяц (entitlement), кеш по hash(version+channel+prompt_ver), дешёвая модель для fit_length, дорогая для tone_rewrite; observability токенов на публикацию.
- **Приватность**: контент клиента ≠ тренировочные данные — провайдер с enterprise-no-retention (или self-hosted open-source модель для чувствительных тарифов); egress-allowlist воркера.
- **Модерация**: перед публикацией фильтр запрещённого контента (собственный список + API модерации площадки где есть), чтобы один workspace не угодил под бан сети из-за чужого контента.

## Интеграция с Publishing
`POST /adapt {version_id, channels[]}` → job → варианты приходят SSE → пользователь выбирает вариант как основу поста (можно смешивать: «этот заголовок + эта середина») → обычный publication flow. AI-вариант хранится как отдельная версия материала (история и диффы сохраняются).

## Риски и снижение
- Галлюцинации фактов → операторы только трансформируют вход, генерация нового факта требует явного режима «написать с нуля» с предупреждением.
- Изменение форматов соцсетей → capabilities обновляются вместе с адаптерами, тесты-канарейки на реальных песочницах.
- Зависимость от одного вендора LLM → router с fallback; контракты внутреннее не завязаны на провайдера.
